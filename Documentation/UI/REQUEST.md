이미지 속 수치·가격·확률은 디자인용 예시이므로 변경하기 쉬운 데이터로 분리해줘.

이미지와 아래 글이 충돌하면 아래에 명시한 최신 규칙을 우선해줘.

[2. 실제 UI 구현]

- 시안 이미지를 통째로 배경에 붙이는 방식은 안 돼.
- 프레임, 아이콘, 버튼, 텍스트, 게이지, 목록을 실제 UI 요소로 구현해줘.
- 플레이어와 같은 손그림 스타일을 유지해줘.
- 필요한 개별 이미지가 부족하면 같은 그림체로 직접 생성해줘.
- 재사용 가능한 공통 버튼, 슬롯, 팝업, 등급 색상, 게이지 구조를 만들어줘.
- 한글이 깨지거나 누락되지 않게 폰트와 텍스트 설정을 확인해줘.
- 팝업 열기·닫기, 탭 전환, 스크롤, 슬롯 선택, 버튼 동작을 연결해줘.
- dim과 입력 차단을 처리해서 UI를 누를 때 뒤의 이동 조작이 함께 실행되지 않게 해줘.
- 기존 게임 데이터와 기능이 있으면 실제로 연결해줘.
- 아직 없는 서버 기능은 교체 가능한 임시 데이터로 구성하고, 실제 서버 연동과 구분해줘.
- 실제 결제·계정연동·네트워크 채팅 등이 완료된 것처럼 꾸미지 마.

[3. 화면 비율 대응]

세로형 디자인 기준의 반응형 UI로 구현해줘.

지원 비율:
- 9:19
- 9:16
- 1:1
- 가로 화면

공통 규칙:
- UI와 이미지를 강제로 늘려 찌그러뜨리지 마.
- 상단 정보와 하단 네비는 화면 가장자리 및 안전 영역을 고려해 배치해줘.
- 화면 높이가 줄면 여백을 조절하고 긴 목록은 스크롤되게 해줘.
- 1:1과 가로 화면에서는 같은 세로형 팝업을 가운데 배치하고 최대 너비를 제한해줘.
- 팝업 높이도 화면 안에 들어오게 하고, 필요한 부분만 스크롤되게 해줘.
- 전체 화면 채팅과 뽑기 결과는 각 화면 비율에 맞춰 전체 화면으로 표시해줘.
- 텍스트, 버튼, 보상, 하단 네비가 잘리거나 서로 겹치면 안 돼.

[4. 화면별 최신 규칙]

메인:
- 프로필 이름과 전투력, 골드·다이아, 설정을 표시해줘.
- 골드·공격력 버프는 작은 아이콘과 남은 시간으로 표시해줘.
- 출석, 룰렛, 버프, 퀘스트, 채팅 진입 버튼이 있어야 해.
- 하단 네비 위에는 원형 스킬 상태 슬롯 8개와 시계방향 쿨타임 마스크를 표시해줘.
- 이 원형 슬롯에는 초 단위 텍스트를 표시하지 마.
- 미션 안내도 시안대로 표시해줘.

하단 네비:
- 스탯, 장비, 스킬, 동료, 유물, 던전, PVP, 상점 순서야.
- 선택한 네비 버튼은 빨간 X로 바뀌어야 해.
- 해당 X를 다시 누르면 팝업이 닫혀야 해.
- 모든 닫기 X는 같은 빨간색 디자인으로 통일해줘.

스탯:
- 캐릭터 레벨은 표시하지 않고 전투력을 표시해줘.
- ×1, ×10, MAX는 전투력 아래와 강화 행들 사이에 배치해줘.
- 스탯에는 일괄강화 버튼이 없어.

장비:
- 갑옷과 몽둥이 모두 최종 몽둥이 화면과 동일한 레이아웃을 사용해줘.
- 상단 선택 장비 스펙 → 총 보유효과 → 아이템 목록 → 일괄강화·자동장착 → 갑옷·몽둥이 탭 순서야.
- 상단 스펙 안의 강화·장착 버튼은 오른쪽 하단에 배치해줘.
- 상단 선택 아이템도 목록과 같은 프레임 및 이미지 아래 수량 게이지를 사용해줘.
- 수량은 1/5처럼 게이지 안에 표시해줘.
- 등급은 카드 왼쪽 위에 표시하고, 별도의 등급 탭은 만들지 마.
- 장착 중인 장비는 체크 표시로 구분해줘.
- 미획득 장비는 어두운 카드와 검은 실루엣으로 표시해줘.

스킬:
- 장착 슬롯은 8개야.
- 장착 슬롯과 보유 목록 모두 해당 스킬의 등급 색을 적용해줘.
- 총 보유효과는 장착 슬롯 아래, 보유 스킬 목록 위에 표시해줘.
- 메인 스킬 팝업에는 총 장착효과와 선택 스킬의 큰 스펙 영역을 넣지 마.
- 일괄강화와 자동장착 버튼이 있어야 해.
- 스킬을 누르면 별도 상세 팝업에서 장착효과, 보유효과, 강화·장착 버튼을 보여줘.
- 수량은 게이지 안에 표시해줘.

동료:
- 스킬 화면과 유사한 구조로 구성해줘.
- 최대 5개까지 장착 가능해야 해.
- 장착 슬롯 아래 총 보유효과, 그 아래 보유 동료 목록을 배치해줘.
- 일괄강화와 자동장착이 있어야 해.

유물:
- 스탯 강화처럼 행별로 표시해줘.
- 공격력·체력 등 관련 효과, 현재 단계, 다음 효과, 강화 성공 확률을 보여줘.
- 개별 강화와 일괄강화가 있어야 해.
- 별도 장착 없이 모든 보유 유물 효과가 전체 적용되는 방식이야.

던전:
- 각 던전 행마다 키 아이콘과 독립적인 일일 도전 횟수 3/3을 표시해줘.

PVP:
- 상단에 실제 해당 플레이어 이미지로 1·2·3위 단상을 표시해줘.
- 그 아래 1~100위 스크롤 랭킹을 표시해줘.
- 순위, 승점, 전투력과 내 순위를 확인할 수 있어야 해.
- 전투 기록은 필요 없어.

상점:
- 뽑기·재화 탭이 있어야 해.
- 뽑기는 갑옷, 몽둥이, 스킬, 동료, 유물 행으로 구성해줘.
- 큰 아이콘은 왼쪽, 정보와 뽑기 버튼들은 오른쪽에 정렬해줘.
- 제목은 “Lv. 3 갑옷 뽑기”처럼 표시해줘.
- 경험치 수량은 게이지 안에 표시하고 “뽑기 경험치”라는 별도 문구는 넣지 마.
- 각 행에 무료 5회 뽑기, 10회 뽑기, 50회 뽑기 버튼이 있어야 해.
- 각 행의 인포 버튼을 누르면 해당 뽑기의 확률 팝업을 열어줘.
- 확률 팝업에는 등급별 전체 확률과 각 아이템의 개별 확률을 모두 표시해줘.
- 개별 확률이 1회 뽑기 기준인지 명확히 표시하고, 등급 합계와 일치하게 해줘.
- 긴 확률 목록은 스크롤 가능해야 해.
- 재화 상품은 큰 다이아 이미지 아래에 수량, 오른쪽에 가격을 표시하고 스크롤되게 해줘.
- 뽑기 결과는 전체 화면이며 장비와 같은 슬롯 디자인을 사용해줘. +1 표시는 넣지 마.

출석·룰렛·퀘스트:
- 보상은 모두 다이아로 통일해줘.
- 보상은 아이콘과 수량으로 표시하고 불필요한 재화 이름을 반복하지 마.
- 출석은 7일, 룰렛은 하루 5회야.
- 퀘스트는 일일·반복·주간 탭과 일괄받기가 있어야 해.
- 반복 퀘스트에 순환 화살표 아이콘은 필요 없어.

채팅·설정:
- 채팅은 작은 팝업이 아니라 전체 화면이야.
- 설정에는 계정연동, 절전모드, 배경음·효과음 조절, 게임종료가 있어야 해.

획득 보상·던전 클리어:
- 최신 24번·25번 이미지처럼 구성해줘.
- 큰 패널, 확인 버튼, 보상 화면 자체의 X 버튼은 없어야 해.
- 어두운 dim 위에 제목과 개별 보상 아이템 프레임·수량을 표시해줘.
- 아이템 프레임에는 해당 등급 색을 적용해줘.
- 보상 뒤에 그림체와 어울리는 노란 후광, 손그림 빛살과 반짝임이 있어야 해.
- “화면을 터치하면 닫힙니다”를 표시하고 dim 영역을 누르면 닫히게 해줘.
- 닫는 터치가 뒤의 게임 조작으로 전달되지 않게 해줘.

[5. 서브 에이전트 병렬 작업]

서브 에이전트를 사용해 독립적인 작업을 병렬로 진행해줘.

- 먼저 메인 에이전트가 모든 시안과 프로젝트를 확인하고 공통 UI 구조와 규칙을 정해줘.
- 이후 화면이나 모듈별로 담당을 나눠줘.
- 같은 씬, 프리팹, 공통 파일을 여러 에이전트가 동시에 수정하지 않도록 파일 소유 범위를 분리해줘.
- 공통 구조 변경과 최종 통합은 메인 에이전트가 담당해줘.
- 에이전트 결과를 기다렸다가 실제로 연결하고 검토해줘.
- 모든 에이전트가 로컬 게임 실행 금지와 GitHub CI 검증 조건을 따라야 해.
- 병렬 작업 자체보다 최종 화면의 일관성과 정상 동작을 우선해줘.

[6. 자동 예약 점검]

이 구현 대화에 연결되는 15분 간격의 자동 후속 점검을 실제로 생성해줘.
새 대화를 매번 만드는 방식이 아니라, 같은 대화에서 문맥을 유지하는 예약으로 설정해줘.

예약 생성 성공 여부와 첫 실행 예정 시각을 알려줘.
도구가 지원하지 않거나 등록이 실패하면 예약됐다고 말하지 마.

매 예약 실행 시:
1. 진행 기록, 에이전트 상태, 최신 커밋과 CI 결과를 확인해줘.
2. 이미 작업 중이면 같은 작업을 중복 시작하거나 실행 중인 에이전트를 불필요하게 중단하지 마.
3. 작업이 멈췄고 미완료 항목이 있으면 다음 작업을 이어서 수행해줘.
4. CI가 실패하면 로그를 확인해 원인을 수정하고 필요한 검증을 다시 실행해줘.
5. 이미 통과한 동일 커밋의 CI를 이유 없이 반복 실행하지 마.
6. 상태가 그대로면 반복 알림은 보내지 말고, 의미 있는 진전·실패·입력이 필요한 문제·최종 완료만 알려줘.
7. 모든 완료 조건을 만족하면 최종 보고 후 이 작업의 예약을 종료해줘.
8. 외부 권한·로그인·사용량 등의 문제로 진행할 수 없다면 성공했다고 처리하거나 같은 실패를 무한 반복하지 말고, 차단 사유와 재개 조건을 남겨줘.

예약 시각을 기다리느라 현재 작업을 멈추지 마.
예약은 중단된 작업을 이어가기 위한 보조 수단이고, 현재 가능한 구현은 계속 진행해줘.

프로젝트에 간단한 진행 기록을 유지해줘.
완료 항목, 남은 항목, 담당 파일, 검증한 커밋, CI 링크, 다음 작업을 기록해서 재개할 때 처음부터 다시 하지 않게 해줘.

[7. 검증]

내 컴퓨터에서 Unity 에디터, 플레이 모드, 게임 또는 로컬 테스트를 실행하지 마.
로컬 파일 읽기·수정과 Git 작업은 진행해도 돼.
실행·테스트 검증은 GitHub Actions 서버에서만 해줘.

- 기존 CI 구성을 먼저 확인하고 활용해줘.
- 필요한 작업 브랜치 커밋·푸시와 CI 실행까지 진행해줘.
- 등록된 UNITY_EMAIL, UNITY_PASSWORD, UNITY_LICENSE 시크릿을 필요하면 사용하되 값을 출력하지 마.
- 컴파일 성공만으로 UI 검증이 끝났다고 판단하지 마.
- GitHub CI에서 가능한 방식으로 UI를 렌더링하고 캡처를 아티팩트로 남겨줘.
- 9:19, 9:16, 1:1, 가로 화면에서 주요 화면을 확인해줘.
- 팝업 전환, 스크롤, 버튼, 장착 상태, dim 닫기, 입력 차단을 검증해줘.
- 캡처에서 잘림, 겹침, 글자 누락, 등급 색, 이미지 투명도 문제를 확인하고 수정해줘.
- 검증이 불가능한 부분은 정확히 구분해서 알려줘.
- 실패를 숨기려고 테스트를 삭제하거나 검증 조건을 약화하지 마.

[8. 완료 조건]

아래가 충족될 때까지 요청 범위 안에서 계속 작업해줘.

- 이미지 25장에 해당하는 화면과 상태가 모두 구현되어 있음.
- 탭·팝업·스크롤·선택·닫기 등 UI 동작이 연결되어 있음.
- 지원 화면 비율에서 주요 내용이 잘리거나 겹치지 않음.
- 기존 전투와 조작에 불필요한 변경이나 회귀가 없음.
- 최신 구현 커밋에 대한 GitHub CI 결과와 가능한 시각 검증을 확인했음.
- 변경 사항이 별도 작업 공간에만 남지 않고 원래 로컬 프로젝트에서도 사용할 수 있게 반영되어 있음.
- 기존 사용자 변경 사항은 보존되어 있음.
