# 전투 최적화 검증 (2026-09-30)

Unity 6000.3.8f1 Windows Editor의 PlayMode에서 측정했습니다. 목표 프레임은 이미 `Application.targetFrameRate = 60`, `vSyncCount = 0`으로 설정되어 있었습니다. 목표 설정과 실제 60FPS 유지는 다릅니다.

## 변경

- 적은 리그 종류별로 풀링하고 가능한 경우 같은 외형을 우선 재사용합니다. 사망한 전투 Actor의 정체성은 재사용하지 않아 이전 투사체가 새 적에게 피해를 주지 않습니다.
- 풀에 보관하는 적은 같은 부모와 본 구조를 유지합니다. 본체 충돌·물리 시뮬레이션·공격 센서·그림자·체력바·얼굴·먼지는 비활성화하고 모든 캐릭터 렌더러를 숨깁니다. 애니메이터는 속도 0과 `CullCompletely`로 평가를 멈추며, 활성 전투에서는 `AlwaysAnimate`로 공격 이벤트를 계속 실행합니다. 재등장 시 파라미터와 공격 콜백을 초기화하고 원래 Idle 클립을 재생합니다.
- 적을 재사용할 때 계층을 옮기거나 Animator 연결을 다시 만드는 비용을 제거했습니다. 다섯 체형의 Move/Attack/Hit/Death 이후 Idle 본 위치·회전·크기를 새 인스턴스와 비교하고, 이전 공격 취소 및 새 공격의 단일 타격 이벤트를 검증합니다. 클립과 컨트롤러 에셋은 수정하지 않습니다.
- 후속 최적화에서 재생성 위치 검색도 별도 격자를 사용합니다. 물리 좌표는 재생성 시작 시 한 번 읽고 새 적을 순서대로 추가합니다. 기존 거리 제곱 1.6, 최대 600회 시도, 난수 호출 순서와 실패 시 마지막 위치 사용을 유지합니다. 체력은 동기적으로 생성하는 한 웨이브 안에서 한 번 계산하며, 보스는 기존 경로로 계산합니다.
- 같은 본 배열을 불필요하게 다시 등록하지 않습니다. 활성 캐릭터의 스킨 메시는 화면 밖에서도 갱신합니다. 빠른 재사용 중 화면 밖 갱신을 생략했을 때 네이티브 빌드에서 몸체가 찢어지거나 사라지는 현상이 재현되어 이 생략을 제거했습니다. 풀에 대기하는 파트는 렌더러가 비활성화되어 Unity SpriteSkin의 변형 대상에서 제외됩니다. 전투 애니메이터와 원본 클립은 그대로 유지합니다.
- 캐릭터·스킬 얼굴 카탈로그 조회를 캐시하고, 변화 없는 틴트·정렬·Transform 쓰기를 줄였습니다.
- 반사광 경계 계산은 각 눈의 행렬과 스프라이트 경계를 한 번 읽어 반복 계산에 재사용합니다. 회전·반전·비균일 크기와 프리팹 수정은 매 프레임 반영하며, 흰 반사광을 마스크로 자르지 않는 방식도 유지합니다.
- 풀 반환 시 얼굴 초기화와 재등장 시 먼지 초기화를 생명주기 콜백에서 한 번 실행합니다. 반사광 계산은 실제 Transform을 0으로 되돌리지 않고 기준 행렬의 이동량을 빼서 계산합니다. 같은 위치를 반복 계산해도 반사광이 누적 이동하지 않는지 검증합니다.
- 같은 스킬 얼굴 프레임·스프라이트·재질을 재설정하는 작업을 줄였습니다. 캐릭터 외형의 Update 동기화도 유지합니다. 이를 LateUpdate만으로 미루는 실험은 철회했으며, 위 스킨 갱신 수정을 하기 전 실행은 최종 성능 수치에서 제외합니다.
- 스킬 위력 계산을 기존 물리 스텝 스냅샷에 캐시합니다. 다음 스텝에는 장비·강화 변경을 다시 읽습니다.
- `GameNumber`의 흔한 지수는 `ObscuredInt`로 보호합니다. 연산마다 암호화 문자열을 만들고 다시 파싱하던 할당을 없애되, int 범위 밖 지수는 기존 보호 문자열과 `BigInteger` 경로를 유지합니다. 외부 저장 문자열 형식, 정밀도, 수치 공식과 변조 감지는 유지합니다.
- 뱀 몸통과 이동형 소환 투사체는 2유닛 격자로 주변 후보를 추린 뒤 기존 선분 충돌 판정을 수행합니다. 타격 순서, 반경, 재타격 간격과 피해량은 유지합니다.
- 가득 찬 체력바는 불필요한 비율 계산을 생략하지만 Inspector의 위치 변경은 반영합니다.
- 스테이지 디버그 재시작도 이펙트를 풀로 반환합니다. 맵은 기존 단일 바닥 렌더러를 유지합니다.
- Windows 실행 검증 중 URP 스프라이트 셰이더가 빌드에서 제거되어 메인 시작이 실패하는 문제를 발견했습니다. `Resources/DoodleIdle/DoodleSprite.mat`의 명시적 참조로 셰이더를 포함하고, 그 재질로 런타임 재질을 생성하도록 수정했습니다.

## 측정 자료

`artifacts/performance/all-skills-companions.csv`에는 스킬 40종과 동료 32종을 모두 실행한 결과가 있습니다. 적 200명을 고정하고 높은 체력을 주는 격리된 시험입니다. 스킬은 종류별 24 게임 초 동안 두 번 시전하고, 동료는 종류별 12 게임 초 동안 실제 투사체 발사를 확인했습니다. 4배속이며, CSV의 프레임 시간과 할당량에는 에디터·테스트 러너 비용도 포함됩니다. 일반 게임 FPS로 해석하면 안 됩니다.

`MainCombatPerformanceSample`은 적 200명으로 시작해 여덟 소환 스킬을 반복 시전하는 스트레스 시험입니다. 120 렌더 프레임 준비 후 300 프레임을 측정합니다. 처치·재생성·보스 전환이 실제로 진행되고 시전 간격이 렌더 프레임 기준이므로 실행별 적 수와 시뮬레이션 시간이 달라집니다. 같은 장면 상태를 재생하는 엄밀한 벤치마크는 아닙니다.

초기 `before.json`은 평균 118.7ms, 프레임당 GC 할당 약 10.28MB였습니다. 1차 스트레스 측정 `final.json`은 평균 43.3ms, p95 155.9ms, 약 1.81MB였고 뱀 처리 마커는 18.7ms에서 2.5ms로 감소했습니다.

후속 측정 `remaining-before.json`은 평균 46.3ms / p95 128.1ms / 약 2.05MB, 최종 `remaining-final.json`은 평균 33.6ms / p95 68.9ms / 약 0.47MB였습니다. 에디터의 과부하 구간에서는 여전히 16.7ms를 초과합니다. 재시작·리필·개별 스킬 마커는 호출 빈도와 전투 상태도 함께 봐야 하며, 프레임 시간과 달리 각 마커의 평균을 합산해 전체 CPU 비용으로 해석하지 않습니다.

일반 속도 메인을 30초 실행한 에디터 측정에서는 초기 평균 18.3ms / 약 0.66MB에서 후속 평균 17.5ms / 약 0.26MB로 감소했습니다. 이동과 타격, 40회 처치, 적 재생성, 동료 발사를 확인했습니다. 최신 재검사 수치는 `normal-main.json`에 있습니다.

## Windows 실행 파일 확인

Unity 6000.3.8f1 Development Build, RTX 4070 SUPER, **720×1080**, 실제 창을 표시하여 렌더링한 결과입니다. 보안 감지 기능을 켰고 기존 저장 데이터를 사용하지 않는 독립 테스트 계정을 사용했습니다. 120 프레임 준비 후 측정했으며, 테스트 수치 보정은 기존 PlayMode 진행 프로필과 동일합니다.

|---|---:|---:|---:|---:|---:|

일반 메인은 40회 처치, 적 오브젝트 201회 재사용, 동료 발사 10회를 확인했습니다. 과부하 시험은 90 렌더 프레임마다 8종을 강제로 추가 시전하여 3,208회 처치, 115회 리필, 적 오브젝트 23,089회 재사용이 발생했습니다. 실제 장착 쿨다운보다 훨씬 많이 겹치는 조건이며, **이 조건의 60FPS 유지는 달성하지 못했습니다.** 모바일 실기기 성능도 아직 확인하지 않았습니다.

결과와 화면은 `artifacts/performance/standalone-normal.json/.png`, `standalone-stress.json/.png`에 있습니다. 두 정상 실행 로그에는 예외나 보안 감지 오류가 없습니다. 창을 숨긴 첫 샘플은 렌더링 배치 0과 검은 화면이 확인되어 성능 근거에서 제외했습니다(`standalone-hidden-invalid.json`). 측정용 시작 스크립트는 런타임 소스에서 제거하고 재현용 사본 `StandaloneCombatSample.cs.txt`만 보고서 폴더에 남깁니다.

최종 확인 빌드는 오류 0건으로 성공했습니다. 이전 빌드에 집계된 예외 4건은 기존 Hot Reload 에디터 창의 `GUIHelper.ConvertToGrayscale` 아이콘 처리에서 발생했으며, `build-diagnostics.txt`에 보관했습니다.

## 후속 최종 검증: 활성 스킨 메시 갱신 포함

최대 장착 장면을 추가로 확인하면서 화면 밖 스킨 갱신 생략 시 일부 몸체가 찢어지거나 사라지는 현상을 발견했습니다. 활성 스킨을 항상 갱신하도록 복구한 **최종 코드**로 측정한 결과입니다. 실행 조건은 위와 같은 RTX 4070 SUPER, Windows Development Build, 720×1080입니다.

| 구간 | 프레임 | 평균 | p95 | p99 | 프레임당 GC 할당 |
|---|---:|---:|---:|---:|---:|
| 일반 메인 | 1,800 | 16.74ms (59.8FPS) | 16.68ms | 18.10ms | 101KB |
| 스킬 8개·동료 5개, 원래 쿨다운, 실행 1 | 1,800 | 17.15ms (58.3FPS) | 19.35ms | 27.10ms | 188KB |
| 동일 최대 장착, 실행 2 | 1,800 | 17.20ms (58.1FPS) | 20.36ms | 28.04ms | 188KB |
| 8종 강제 반복 중첩 | 600 | 22.96ms (43.6FPS) | 42.07ms | 48.48ms | 219KB |

최대 장착 시험은 독립 테스트 프로필에서 슬롯을 해금한 후 원래 1스테이지 필드로 돌아와 진행했습니다. 원래 공격력·적 체력 공식과 스킬 쿨다운을 사용했으며, 각 실행에서 자동 스킬 발동 28회, 동료 발사 54회, 처치 1,498/1,602회와 재생성 70/74회를 확인했습니다. 강제 중첩 시험은 이전 비교 조건을 유지하기 위해 실제 장착 1개·동료 1개인 상태에서 8종을 별도로 반복 시전합니다. 일반 및 최대 장착 결과와 혼동하지 않습니다.

최종 파일은 `mesh-final-normal.json/.png`, `mesh-active-update-1.json/.png`, `mesh-active-update-2.json/.png`, `mesh-final-stress.json/.png`입니다. 이 네 실행 로그에는 예외·보안 감지 오류가 없습니다. 최대 장착 두 실행의 활성 몸체 917/922개 파트와 강제 중첩 794개 파트의 변형 정점을 확인했으며, 각 화면도 직접 확인했습니다. 실제 창을 표시한 렌더링 결과입니다.

이전 네이티브 강제 중첩의 23.02ms / p99 65.64ms와 비교하면 평균은 비슷하지만 p99 지연은 48.48ms로 줄었습니다. 실행 시간이 달라 실제 처치·재생성 횟수가 완전히 같지는 않습니다. **극단적 중첩에서 고정 60FPS는 달성하지 못했고, 모바일 실기기는 아직 미검증입니다.**

재생성 세부 계측은 Stopwatch로 확인했습니다. 생성 위치 검색은 새 적 한 마리당 평균 약 10.0µs에서 1.2µs로 감소했습니다(`overload-timed-before.timings.csv`, `overload-visual-after.timings.csv`). 일부 Unity ProfilerRecorder 마커는 유효한 시간을 수집하지 못해 `*.invalid-markers.csv`로 구분하고 근거에서 제외했습니다. 스킨 수정 전 `overload-final-*`, `mesh-early-sync`, `mesh-confirm-*`는 진단 자료이며 최종 성능 자료가 아닙니다. 임시 계측·실행 스크립트는 Assets에서 제거하고 보고서 폴더의 `.cs.txt`로 보관합니다.

## 동작 유지

`DoodlePerformancePortraitTests`는 선분 충돌 후보가 기존 전수 검사에서 잡히는 적을 누락하지 않는지, 타격 순서와 스킬 스냅샷 값이 유지되는지 검증합니다. 기존 전투 검사로 공격 이벤트, 피격, 이동 간격, 스킬 수명·타격 횟수, 보스 전환, 재생성, 풀 상태 초기화를 확인합니다. 테스트용 적 고정·4배속은 테스트 인스턴스에만 적용하고 테스트 프로필과 시간 배율을 복원합니다.
